## 三、方案修正：单次跑不能当「结果」

### 用户的质疑（成立）

> 「如果全是单次跑的话那得出来的 keyword_recall 有什么意义，因为可能同一个配置再跑一遍它的 keyword_recall 又会不一样了，只有测出了噪声带再用平均值去对比才有意义吧」

**对。** 精确的说法是：

```
单次 keyword_recall = 0.72
        ↑ 不是「cs=400 的得分」，是「这一次抽样恰好抽到的票」
```

**单次跑只能干一件事：检出【大于噪声带宽】的差距。**

```
检出了大差距   → 可以下结论
检不出差距     → 只是「这次票不够」，不等于「两者一样」
```

> **「没检出差异」≠「没有差异」。** 小差距区间单次跑是「不知道」，不是「相等」。

**而且 5 轮不只是取平均 —— 它把敏感度提高约 3 倍：**

```
单次跑：抽 1 张票     → 不确定性 ≈ 噪声带宽 0.05~0.07
5 轮均值：抽 5 张票   → 标准差 ÷ √5 → 不确定性 ≈ 0.02~0.03
```

### 改成

```
② vs ③（判 cs）    预期差距【小】→ 直接上 5 轮（100 次）
① vs ②（判 top_k） 预期差距【大】→ 先单次筛（20 次），接近再补 5 轮
```

**③ 的 5 轮还有个白捡的好处**：能直接和 9/15 的 `[0.74, 0.77]` 对照，等于免费校准仪器。

## 四、代码改动（今天的交付物）

### 4.1 修掉 9/23 记的两个洞

**洞①：`run_noise()` 不写 `gen_config.json`**（只有 `_run()` 写）

⚠️ 这比「戳是旧的」更危险 —— 它是个**陷阱链**：

```cmd
python src/generator.py --top-k 6 --runs 5     :: answers.json 没变！还是上一个配置的
python src/keyword_recall.py --noise           :: 只看 band，没事
python src/keyword_recall.py --record          :: ← 灾难
```

`--record` 读的是 `answers.json`（**上一个配置的答案**），却盖 `cs=400 + top_k=6` 的戳
→ 总账里出现一条 **配置合法、数字错配**的记录，**没人会怀疑它**。

**修**：`run_noise()` 也写 `gen_config.json`，且带 `runs`。

**洞②：`_sweep_key` 不含 `runs`**

```
改前：(cs, ov, top_k, side)
改后：(cs, ov, top_k, runs, side)
```

**为什么必须加**：`1 轮` 和 `5 轮` 是**两次不同的测量**，不是同一条配置。
5 轮贵 5 倍，如果共用一个 key，**一次顺手重跑就把它冲掉了**。

`evaluator.py` 的同名函数**同步改**（两个 `_sweep_key` 必须形状一致 —— 这是 9/18 那个静默 bug 的教训）；检索侧没有 `runs` 字段 → `.get("runs")` 恒为 `None`，不影响原有 4 条。

**洞③（新发现）：`--noise` 模式不能记账**

**修**：`--noise --record` 记【5 轮均值 + 噪声带】：

```json
"metrics": {"keyword_recall": 0.7370, "noise_band": [0.7197, 0.7442]}
```

### 4.2 新增：逐题噪声统计 `per_question_noise()`

```
每题返回 {id, total, score_mean, score_lo, score_hi}
```

**为什么总分不够**：总分只给一个数，看不出**是哪几题在动**。

```
9/15 实测：20 题里只有 #6 #7 #8 #13 #20 会晃
          #20 一个人在 0.33↔1.00 之间跳，凭它一题就能拉动总分 0.033
→ 两个配置差 0.03 时，必须翻这张表才知道是噪声还是真差异
```

`--noise` 现在会直接**列出会动的题**。

### 4.3 ★ 新增：抗断能力（重试 + 断点续跑）

**起因**：③ 第一次跑到第 17 题时撞上 `RemoteDisconnected`，**80 次调用白花，0 条数据**。

**根因**：`generate_all` 是「全有或全无」——

```
现在的设计：100 次调用全在内存 → 跑完才落盘 → 中途炸 = 全丢
```

**改法分两层：**

**(a) 重试** —— `_call_once()` 区分「值不值得重试」

```
瞬时故障（ConnectionError / Timeout / ChunkedEncodingError）→ 等 1s→2s→4s 重试，共 4 次
服务端 5xx                                                  → 也重试
客户端 4xx（key 错 / 参数错）                                → 【立刻抛】，不浪费时间
```

**(b) 断点续跑** —— 每答完**一题**存一次 `data/_progress.json`

```
_save_progress()   先写 .tmp 再原子改名（防写一半坏掉）
_load_progress()   配置对不上就作废（换 top_k/runs 不接旧进度 = 不串味）
_clear_progress()  正式产物落盘后清掉
```

### ★★ 4.4 一个必须记住的设计判断

**断点为什么不直接写进 `answers_multirun.json`？**

```
如果断点直接写正式文件：
   跑到第 17 题崩 → 文件里躺着 16 题
   → keyword_recall 的 compute_noise_band 读它
   → 【若无其事照算】，给出基于 16 题的假噪声带
   → 数字看起来完全正常              ← 静默 + 看起来正常

所以：半成品只能住 _progress.json，正式文件只写【完整的】
```

> **这就是「为什么要这样写」。代码怎么写可以查，这个判断查不到。**
> 它和 9/18（key 撞车）、9/21（少 1）、9/23（标签泄漏）是同一个形状：
> **数字变好看 / 看起来正常 + 完全静默。**

**⚠️ 补一句**：今天这次崩溃是**「响亮地失败」**（一个文件都没写），反而是好情况。
真正难防的是**「悄悄写了一半」**——那样 `compute_noise_band` 会照算不误。

### 4.5 涉及文件

```
src/generator.py      重试 + 断点 + run_noise 补写戳 + 头部注释补「抗断」一节
src/keyword_recall.py _sweep_key 加 runs + per_question_noise + --noise --record
src/evaluator.py      _sweep_key 同步加 runs
.gitignore            忽略 data/_progress.json / _progress.tmp
```

## 六、★ 五个发现（今天的重头戏）

### 发现① 今天的噪声带 `[0.72, 0.74]` 是**错的**

```
9/15 测的带：[0.74, 0.77]     宽 0.03
今天测的带： [0.72, 0.74]     宽 0.02
                ↑ 两条带只在一个点上碰着（0.74）
```

**两次独立测量，各自都说「只有 0.02~0.03 宽」，却几乎不重叠。**

```
唯一合理的解释：5 个样本【测不出】真实带宽
合并 10 个样本：0.72 ... 0.77  → 真实带至少 0.05 宽
```

**9/15 的 log 自己预言过**（「5 次抽样的 min/max 会低估真实范围」）—— **今天实测撞上了**。

> **⚠️ 直接后果**：拿今天的 `[0.72, 0.74]` 当尺子，会把一个 **0.03** 的差异判成「显著」，
> **但它其实在噪声里。今天往后，尺子用 0.05。**

**而且这条修正了我 9/23 的一个说法** —— 9/23 写「差异 > 0.05 直接下结论」，
按 10 个样本合并后的带宽，**这个阈值偏乐观**，改 **0.07** 更稳（9/15 log 就是这个数）。

### 发现② `#20` 的低分是**尺子的缺陷**，不是模型的错

```
题面：  Give two examples of green infrastructure mentioned in the document.
标准答案：Green infrastructure, such as parks, wetlands, and green roofs,
        enhances urban resilience by managing stormwater, reducing heat,
        and improving air quality.          ← 整句【定义】，15 个关键词

模型答：Two examples ... are parks and wetlands.   ← 【完全正确】
得分：  5/15 = 0.33
```

**漏掉的 10 个词是 `stormwater / heat / air quality / resilience / enhances...` —— 题面压根没问这些。**

```
keyword_recall 的分母 = 【标准答案的全部关键词】
→ 它要求模型把标准答案里所有词都说出来，包括题面没问的
→ 模型【老老实实回答被问到的问题】→ 被判 0.33
```

**这不是噪声，是尺子的系统性偏差。** 而且它**双峰**：要么 0.33（只答例子），要么 1.00（顺手把定义抄一遍）—— 9/15 有 4 轮吐出了整句定义。

**决定：不修。** 修法是把标准答案改成只含题面问的（`parks, wetlands, green roofs`），
但 `eval_set.json` 一改 → `gold_chunks.json` 就失效（它是拿答案文字去块里匹配的）→ 得重跑 `make_gold_chunks` → `#20` 的 gold 块可能变 → **9/18 那 4 条检索记录就变成「用旧考卷算的」**。连锁反应大于收益。

**对策**：对比时**单独看 `#20`**，并同时报一个「剔除 #20 的 19 题均值」。

### 发现③ 「会动的题」这份名单，**本身也是抽样的**

```
9/15 会动的： #6 #7 #8 #13 #20     （5 题）
今天 会动的： #6 #7 #8 #13         （4 题）← #20 不见了
```

**`#20` 不是「变稳定了」** —— 它是双峰的，9/15 抽到 4 高 1 低，今天 5 张票全抽到低。

> **教训：不能把「会动的题」当成题目的固有属性。**
> 那是一次抽样的结果，和分数本身一样会晃。

### 发现④ `#20` 一个人解释了 **113%** 的差异

```
 #     9/15    今天      差
 6    0.976   0.988   +0.012
 7    0.200   0.233   +0.033
 8    0.923   0.908   -0.015
20    0.600   0.333   -0.267   ← ★
其余 16 题：一模一样

总分差 = -0.0118
#20 单独贡献 = -0.0133   = 总差异的 113%

剔掉 #20 之后：
  9/15: 0.7567
  今天: 0.7583
  差:   +0.0016   ← 几乎为零
```

**两次跑，除了 `#20` 那个硬币，其余 19 题完全一致。**

### 发现⑤ ★ 同分不同病

`#20` 是 0.33、`#7` 是 0.23，**在分数表上长得一样，病因完全不同**：

| # | gold 名次 | 进前 3？ | 分数 | **病因** |
|---|---|---|---|---|
| #6 | 1 | ✅ | 0.99 | 正常 |
| **#7** | **5** | **❌** | **0.23** | **真信号**：模型**根本拿不到**含答案的块，它诚实地说「资料里没有」 |
| **#8** | **4** | **❌** | **0.91** | **侥幸**：`wind/solar/hydroelectric` 是常见词，别的块里也有 → 蒙对了词 |
| #13 | 1 | ✅ | 0.98 | 正常 |
| **#20** | **1** | **✅** | **0.33** | **假信号**：模型答对了，是**尺子**的错 |

**看 `#7` 的答案原文（同一个 context，5 轮）：**

```
轮1：说了 mitigation and adaptation，但引的是【另一块】的话          → 0.33
轮3：does not explicitly name ... cannot be answered with a pair     → 0.17
轮5：很细致的解释，但结论仍是「资料里没明说」                        → 0.25
```

**模型没有幻觉，它在如实报告「你给我的资料里没有这个答案」。**

> **`#7` 是「赢了检索、输了生成」的【反面案例】：检索输了，生成诚实认输。**
> **`#20` 是尺子坏了。** **`#8` 是蒙对了词，尺子给了它不该给的奖。**
>
> **分数低 ≠ 有问题。分数相同 ≠ 病因相同 —— 必须看逐题 + 名次 + 原文。**

## 七、对 ② vs ③ 的预测（可证伪）

**用总账里 9/18 存的 `gold_rank` 查（不用重跑 —— 这就是「存原始数据不存加工结果」的价值）：**

```
 #    cs=400      cs=800     ← top_k=3 时进不进前 3
 6    1(进)       1(进)
 7    2(进)       5(★不进)    ← ★
 8    2(进)       4(★不进)    ← ★
13    1(进)       1(进)
20    1(进)       1(进)
```

```
③ (800,160) top_k=3  →  #7 名次 5 > 3  →  【拿不到答案】
② (400,160) top_k=6  →  #7 名次 2 ≤ 6  →  【拿得到答案】
```

**预测：**

```
如果 ② > ③，差异应该集中在 #7（可能还有 #8）
#7 大概会从 0.23 跳到 0.8 上下

⚠️ 如果 ② 赢了，但赢在【别的题】上 → 这个解释就错了，要重想
   （这就是它是个真实验、不是走过场的原因）
```

**⚠️ 两支预防针：**

```
针①：效应可能【小于噪声带】
    #7 从 0.23 → 0.80，摊到 20 题只有 +0.029，而带宽 0.05
    → 平均分很可能【看不出】这个改善
    → 但逐题看得清清楚楚：模型终于拿到了答案

针②：#20 会捣乱
    如果 ② 抽到 1.00、③ 抽到 0.33，凭空差 0.033
    → 必须单独看 #20，并同时报「剔除 #20 的 19 题均值」
```

> **可能的结论是「平均分分不出胜负，但机制上 cs=400 让 #7 答对了」**
> **—— 这是个完全正当、而且很有价值的结果，不是实验失败。**

### 11.4 ★★ 新发现⑦（今天最有价值的一条）

**「gold 在不在 context 里」同时决定了【分数】和【方差】—— 两者是同一个病。**

```
cs=800 时 gold 排不进前 3 的题： #07(rank 5)  #08(rank 4)      ← 恰好就这两道

③ 里晃得最狠的题（按晃幅排序）：
   #08  晃 0.46   ← gold 没进 context
   #07  晃 0.17   ← gold 没进 context
   #13  晃 0.11
   #06  晃 0.06
   ★ 前两名，正是那两道 gold 没喂进去的题
```

**喂进 gold 之后（②），这两题同时被治好 —— 分数上去 + 方差归零：**

| # | ③ 分数 | ③ 晃动 | ② 分数 | ② 晃动 |
|---|---|---|---|---|
| **#07** | 0.233 | 0.17 (0.17~0.33) | **0.875** | **0.00** (0.88~0.88) |
| **#08** | 0.908 | **0.46** (0.54~1.00) | **1.000** | **0.00** (1.00~1.00) |
| #06 | 0.988 | 0.06 | 0.941 | 0.00 |
| #13 | 0.978 | 0.11 | 0.878 | 0.11 ← 没治好 |

**机制**：gold 不在 context 里时，模型只能靠**参数记忆**作答 —— 既答不准（低分），又**每次即兴发挥都不一样**（高方差）。
把含答案的块喂进去，它就从「即兴」变成「读材料」，**低分和高方差同时消失**。

> **所以：低分和高方差不是两个问题，是一个问题的两个面 —— 都是「材料里没有」的症状。**
> 看到一道题又低分又晃，第一件事不是调模型，是**查 gold 名次**。

**反面同样成立**：② 里新冒出的会动题 `#01/#03/#16`，gold 在两套配置里都在 context 内
→ 它们的小幅晃动**不是**「材料缺失」，是**关键词覆盖在及格线附近**，属于另一种病。
**「方差」至少有两个来源，别都归到 gold 上。**

### 12.5 ★★★ 发现⑩：尺子在奖励「抄源句」（决定性的）

**② 领先 ① 的 0.0385 拆开（60% 来自 #08 一题）：**

```
 #     Δ       真假      原因
 8   +0.462   尺子   ← 见下
 3   +0.138   噪声   ← ② 自己在 0.54~0.77 晃，① 稳定 0.538

13   -0.022   真实   ← ② 更差（还蹦出中文「参考资料」）
 → 真正属于「尺子奖励」的：#08 + #01 = 0.524/20 = +0.0262，占总差异 68%
```

**`#08` 的原文（同一道题，两个答案都对）：**

```
题：What renewable energy sources does the document mention?

① k2 (104字, 7/13 = 0.538):
   "The document mentions ... : - Wind  - Solar  - Hydroelectric power"
   ← 【完全正确】，题目问的它全答了

② k6 (361字, 13/13 = 1.000):
   同样三行，然后【把源句整段抄了一遍】：
   > "Transitioning to renewable energy sources, such as wind, solar, and
      hydroelectric power, is crucial for reducing greenhouse gas emissions."
   ← 多出的 6 个词 crucial/emissions/gas/greenhouse/reducing/transitioning
     【全部来自题目没问的那半句】
```

**`#01` 同理**：① 12/13（缺 `particularly`），② 13/13 —— ② 只是多写了源句里的副词。

**机制**：

```
keyword_recall 的分母 = 【标准答案的全部关键词】
而标准答案【本身就是源文档里的一句话】
→ 模型把源句抄得越全 → 命中越多 → 分越高
→ 【尺子奖励「抄源句」，不区分「抄来的废话」和「答出来的内容」】
```

**这和发现②（`#20` 尺子缺陷）是同一个病的两面：**

```
#20：模型答对了（只答被问的）→ 判 0.33        ← 惩罚「不抄」
#08：模型答对了 + 顺手抄了源句 → 判 1.00      ← 奖励「抄」
同一套题，同一把尺子，两种命运 —— 【差的不是答案，是抄没抄】
```

### 12.6 ★★ 发现⑪：`#07` 在 ① 和 ② 里是【逐字相同】的答案

```
① k2 (410字, 21/24):  缺 ['approach','pronged','requires']
② k6 (408字, 21/24):  缺 ['approach','pronged','requires']
```

**多喂的那 4 块，对 `#07` 起了【零作用】** —— 正如 11.8 推断的：`cs=400` 时 gold 排在**第 2 名**，
① 的 2 块里**已经含了那块**，所以 ② 多出来的 4 块不是答案来源。

→ **11.8 那个「归属模糊」关掉了：多喂的块对 #07 没有贡献，涨的全是 cs 的功劳。**

### 12.7 结论：选 ①（cs=400, top_k=2）

| 配置 | 索引 | 每次喂 | 均值 | **真实质量** | 每次上下文 |
|---|---|---|---|---|---|
| ③ cs=800 k=3 | 114 块 | 3 块 | 0.7370 | `#07` **答不出来**（gold 没进） | ~2400 字 |
| ② cs=400 k=6 | 302 块 | 6 块 | **0.7755** | `#07` ✅ | ~2400 字 |
| **① cs=400 k=2** | 302 块 | **2 块** | 0.7371 | `#07` ✅ | **~800 字** |

```
① 和 ② 的真实质量【一样】：#07 逐字相同；#08/#01 差别是尺子奖励抄写
① 只用 1/3 的上下文
③ 的真实质量【确实更差】：#07 因为 gold 没进 context 而答不出来（真信号）
→ 【选 ①】

⚠️ 代价：索引从 114 块变 302 块（2.6 倍向量，一次性 + 存储）
```

> **只用均值会选 ② —— 为「抄源句」多付 3 倍 token，白花。**
> **读答案才会选 ① —— 这才是今天整场实验的兑现。**

**⚠️ 诚实边界**：① 的信息饱和结论**只对这套 20 题成立**（天花板分析用的是这 20 题的参考关键词）。
换成别的语料，`top_k=2` 未必还够 —— 要重标题、重做天花板分析。
**这不是「top_k=2 万能」，是「在这 20 题上，2 块已经够了」。**

### 12.8 阶段 4 遗留：prompt 模板实验的可证伪预测

按发现⑩，**改 prompt 让模型「简短作答」会让 keyword_recall 掉分** —— 因为它少了抄源句的机会。

```
预测：加一句「用一到两句话简短回答」→ 均值【下降】（可能 0.74 → 0.70 量级）
如果下降 → 独立证实「这个指标在奖励抄写」
如果不降 → 发现⑩ 的解释错，要重想
```

**这个预测把「尺子有病」从解释变成了可检验的东西** —— 是第 7 周最后一个参数实验的最佳形态。
