### 2.2 关键坐标：**gold 就是块编号**（今天自己挖出来的）

```

#17 [HIT] gold=[171, 172]  ← 两个编号 = 答案横跨重叠区
```

**全链用同一套坐标（chunk index），所以 `hit()` 才能写成三行：**

```python
def hit(retrieved, relevant):
    return bool(set(retrieved) & set(relevant))   # 同一套坐标 → 直接比数字
```

> 如果当初 `ranked` 存的是文本而不是编号，这里就得做字符串匹配。

```python
def int_arg(name, default):
    """两种写法都认：--name 400  或  --name=400"""
    for i, arg in enumerate(sys.argv):
        if arg == name:                 return int(sys.argv[i + 1])
        if arg.startswith(name + "="):  return int(arg.split("=", 1)[1])
    return default
```

**同一个模式：写死的常量 → 命令行参数。** 只是这次取字符串不是整数（不能照抄 —— 这是好事）。

## 八、关于「学了就忘」

用户的自我诊断：**「看一遍又不知道自己是干什么的，说到底是理解不透彻」** —— 诊断准确。
但补一句：**这个现象是正常的，而且原因是「重读」这个手段本身弱。**

```
重读：舒服（"我又看懂了"）、几乎不产生留存
今天做对的：读 5 模块 → 跑命令 → 发现 gold 是块编号 → 数 rank=2 有几个
           → 5 个 → 20-5=15 → 对上 hit@1=0.75     ← 【这个「数一遍」就是留存机制】
```

> **复习 = 再做一遍小事，不是再看一遍字。**
> 「每周手写练习 ×3」不是作业，**它就是抗遗忘机制本身**（所以它在「雷打不动」那一栏）。

**一个现成但没用的资源**：`git log --oneline` —— **19 条提交，每条标题就是一节课**，
每条都能 `git show` 出当时的 diff。**有这份语料，但还没拿它复习过。**

### 复习该怎么做（建议：半天，0 元 API）

```
① 合上代码，从 txt 画到两个指标 —— 画不出的那一环就是没记住的
② 默写 6 个核心函数
③ 跑起来对照 src/ diff —— ★ diff 出的 bug 就是「哪里没记住」的精确地图
④ 【最后】才看 log
```

> **顺序不能反：先默写再看答案。** log 是答案，先看就没默写了。

**注意第9周那行是另一件事**：

```
第9周 | [ ] 手写「RAG 调优过程」复盘   ← 实验复盘（改了什么、分数怎么变、为什么）
这次要做的                              ← 代码理解（参数为什么这么设计）
```

**两件事，两个机制。** 不用新造计划，只要认出它们分开。

**「之后学习中逐渐加深」有个前提**：后面的学习要**碰到**前面的代码。
第8周 Streamlit 套界面，正是第5–7周代码**第一次被外部调用**的时刻 ——
那时问「这个接口为什么长这样」就是加深。**但只 import 一下不会加深 —— 加深要设计。**
