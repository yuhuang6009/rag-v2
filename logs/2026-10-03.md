## 三、任务 B：`--prompt` 改造

### 3.1 三个判断（设计依据）

```
判断一  prompt 必须进 _sweep_key
        → 否则 v1 和 short 的 key 相同 → 跑完 v1 再跑 short，v1 被【覆盖】
        → 实验根本做不出来（9/27 那个坑的原样重放）

判断二  断点校验必须覆盖 prompt
        → 否则 v1 跑到一半改成 short 重跑 → 接着 v1 的断点
        → 得到【半 v1 半 short】的数据，_clear_progress 事后又把断点清掉 → 完全看不出

判断三  未知 prompt 名必须响亮报错
        → 否则 --prompt shrot 拼错 → 静默回退默认 → 你以为测了 short、其实跑了 v1
        → 结论全错，而分数完全正常
```

### 3.2 阴性对照（证明测试有资格当测试）

```
新代码：v1 key=(400,160,2,5,'v1','generation')
        short key=(400,160,2,5,'short','generation')     → 不同 [OK]

旧代码：v1 key=(400,160,2,5,'generation')
        short key=(400,160,2,5,'generation')             → 相同 [FAIL] 会互相覆盖
```

**→ 新代码那 12 个 [OK] 的含金量，全部来自「旧代码在这里是 FAIL」。**

### 3.3 真实实验里的活证据

跑完 v1 之后，账本从 9 条变 10 条，**而且是新增不是覆盖**：

```
#8  generation cs=400 k=2 runs=5 prompt=None   mean=0.7371   ← 9/27 那条，还在 ✅
#9  generation cs=400 k=2 runs=5 prompt='v1'   mean=0.7381   ← 今天新添
#10 generation cs=400 k=2 runs=5 prompt='short' mean=0.6203  ← 今天新添
```

**三条并存 = 修复在真实场景里生效了。**（如果 prompt 没进 key，#9 会顶掉 #8。）

### 3.4 顺带搞清一个细节

```
账本里「覆盖」和「新增」的位置是一样的 —— 都是先滤掉同 key 的、再 append 到末尾。
→ 所以读账本别靠"第几条"认记录，要靠 config 认。
```

> （也说明我推荐「两个都重跑」是多花 100 次买了个安心 —— 结果证明只跑 short 也够。
> 但既然买了，就把它当发现用：现在手里是实测结论，不是猜测。）

### 发现 2：**答案在变 ≠ 分数在变**

```
v1 组：20 题里 5 题的【答案文本】在 5 轮之间有 2-3 种版本
       但【分数】会动的只有 2 题（#06 #13）

     #12 / #16 / #20 的答案 5 轮里确实不一样，
     但它们变的那几个词，恰好不在【标准答案的关键词表】里 → 文本动了，分数没动
```

> **噪声不是均匀洒在所有题上的。**
> 答案会不会变是随机的；**变了会不会反映到分数，取决于它离关键词边界有多远。**
>
> 这补全了 9/27 的结论（「分母越小晃得越狠」）：
> **分母小是"离边界近"的一个原因，另一个是答案本身在边界附近游走。**

### 发现 3：**「哪几题在动」是可复现的**

```
9/27 会动的题 : #06  #13
今天会动的题 : #06  #13      ← 一模一样
```

**两次独立运行，晃动的题是同一批。**

> 这意味着「噪声」不是纯随机 —— 它有两个成分：
> **一部分是每次抽签（不可复现）**，**另一部分是这几道题本身就在临界点上（结构性的）**。
> 后一部分占了主导，所以两次都对上了。
>
> 实践含义：**判「A 和 B 谁更好」时，先看是不是这几道临界题在动** ——
> 如果是，那差距大概率是结构噪声，不是真差异。

## 六、★ 为什么降这么多：尺子有两条降分路

### 6.1 两张表

**表 1：v1 组里，答案越长分越高**

```
20 题：答案字数 vs 分数    相关系数 r = +0.434
```

**表 2：掉分的题 = v1 答案长的题**

```
掉分的 10 题：v1 平均 338 字
不动的 10 题：v1 平均 136 字
```

**合起来是一句话：**

> **v1 那 0.118 分里，有一半是「用字数买来的」。**

- **不动的 10 题**（136 字）：v1 本来就答得紧，short 没得砍 → 分数一分不动
- **掉分的 10 题**（338 字）：v1 在灌水，砍掉水就掉分

### 6.2 两条路

```
路①（我预测到的）：不能抄 → 丢掉借来的关键词
路②（我漏掉的）：  必须改写 → 踩中尺子的已知缺陷
                    optimize → optimizing    尺子判【没命中】（词形变化，缺陷③）
                    warming  → rising        尺子判【没命中】（同义词，缺陷①）
                    enhance  → enhancing     尺子判【没命中】（词形变化，缺陷③）
```

**量了一下（自动可测的部分）：**

```
丢掉的 39 个关键词里，10 个是「说了，但换了词形」= 26%
★ 这是【下界】 —— 同义词（warming/rising、acidity/acidification、contribute/cause）
  机器测不出来，要人眼看，真实比例更高
```

### 6.3 两个反例（我把它们当证据）

**反例 A —— 字数本身不加分（`#12`）**

```
#12  v1 248 字 → short 114 字     分数【完全相同】：9/14

v1   : "Two economic costs are: 1. Damage to infrastructure  2. Reduced agricultural productivity
        (These are explicitly listed in the "Economic Impacts of Climate Change" section...)"
                                                        ↑ 这 60 字是纯灌水，一个关键词都没带
short: "Two economic costs mentioned are damage to infrastructure and reduced agricultural productivity."
```

**v1 多出来的 134 字 = 零分数。** 反过来，`#14`、`#18` 的 short 版本字数还**变多**了，分数照样不动。

> **所以不是「字多分就高」这么粗暴 —— 是「字的构成」。**
> 抄源句的字带关键词 → 加分；"根据参考资料"这种字 → 不加分。

**反例 B —— 更好的答案被扣了分（`#13`）★ 最漂亮的一例**

```
标准答案：AI and machine learning can optimize energy use, predict climate patterns,
         and enhance climate resilience. Applications include smart grids,
         climate modeling, and precision agriculture.

v1    (886字!) 0.956  ← 长篇大论，把源句抄了个遍
short (247字)  0.667  ← 丢了 6 个词

short 的原文：
  "AI and machine learning can help address climate change by optimizing energy use
   (e.g., in smart grids), predicting climate patterns and impacts, enhancing climate
   resilience, and supporting precision agriculture and efficient resource management."
```

**这段 short 把标准答案的每一个实质点都覆盖了** —— optimize / predict / enhance / smart grids /
precision agriculture，一个不漏。**它比 v1 那段 886 字的废话写得好。**

**但它的得分是 0.667，v1 是 0.956。** 丢的 6 个词里 3 个是
`optimize→optimizing`、`predict→predicting`、`enhance→enhancing`。

> **这段答案更短、更准、更好读，被扣了 0.289。**
> **扣它的不是「答得不好」，是「没照抄」。**

## 七、★ 结论：尺子能测出 prompt 变了，但判不了哪个更好

### 7.1 把 9/27 的发现⑩ 精确化

9/27 说「尺子在奖励抄源句」。今天说得更准：

```
不是「奖励抄」这么简单，是：

  分数 ≈ 【标准答案的关键词，你凑齐了几个】
          —— 跟你【另外还说了多少】完全无关

  而标准答案本身就是源文里的一句话（make_gold_chunks.py 的 ans in cn 那个耦合点）
  → 凑齐它们最省事的办法就是【把源句抄回来】
  → 于是：话多（抄）分高，话少（概括）分低      r = +0.434 就是这个的实测值
```

### 7.2 直接后果

```
short 的答案【普遍更好】（更聚焦、没有"根据参考资料"这种废话、语义完整）
但分数低 0.118

如果只看这个数，结论会是「short 更差」——【错误的结论】
因为分数变化的主体不是「答案质量」，是「答案长度 + 抄写程度」
```

### 7.3 第7周最后一个参数的诚实结论

> **这个指标能测出 prompt 变了（0.118，远超噪声带），但测不出「哪个 prompt 更好」——
> 因为它对「长短」和「照抄」有系统性偏好。**
>
> 要判 prompt，需要一把**不惩罚简洁**的尺子：
> 长度归一化 / 语义判分 / LLM 当裁判。

**这是一个有价值的负结果，不是失败。**
它把「我的评测指标有什么盲区」从一句话变成了**可检验的东西**，而且顺手拿到了判它的方法。
