## 一、今天做了什么

### 1. 新建 `src/keyword_recall.py`（生成侧指标）

| 函数 | 干什么 | 返回 |
|---|---|---|
| `keywords(text)` | 清洗一段文本 → 关键词**集合** | `set` |
| `keyword_recall(gt, gen)` | **单题**分数 = 命中词数 ÷ 标准答案词数 | `float` / `None` |
| `compute_keyword_recall(eval_set, answers)` | **20 题**平均 + 逐题明细 | `(avg, rows)` |
| `compute_noise_band(eval_set, multirun)` | 同配置跑 N 轮的波动范围 | `(每轮分数, min, max)` |

**`keywords()` 四步**：转小写 → 标点变空格 → 切词 → 去停用词和单字符。

**为什么要停用词**：不滤掉的话，任何一段英文都能命中一堆 the/of/and → **分数虚高，而且虚得「看起来很正常」**——这是最危险的一种错。

**算分公式**：`len(gt_kw & gen_kw) / len(gt_kw)`（集合交集，和 evaluator 里 `hit()` 一个套路）。

### 2. `generator.py` 加 `--runs N`（多轮生成）

```
python src/generator.py             → data/answers.json           每题 1 个答案（faithfulness 用）
python src/generator.py --runs 5    → data/answers_multirun.json  每题 5 个答案（噪声带用）
```

**为什么两个文件不合一个**：两个产物的**读者不同**。
- 噪声带要「同配置重复多次」
- faithfulness 要「一份确定的答案 + context 快照」

混在一起以后会乱。

**为什么 20 题只存一份 `context`**：同一题每一轮给大模型的资料**完全相同**（检索是确定性的，embedding 逐位一致）。变的是答案，不是材料。

### 3. 实测噪声带

```
第 1 轮：0.75    第 4 轮：0.75
第 2 轮：0.74    第 5 轮：0.74
第 3 轮：0.77
噪声带 = [0.74, 0.77]   波动 0.03
```

**逐题看方差**：只有 #6 #7 #8 #13 #20 会动，**#20 一个人就贡献了约 0.033**（它的分数在 0.33 和 1.00 之间跳）。

**结论**：5 次抽样的 min/max 会**低估**真实范围。实操上把 `[0.72, 0.79]` 当噪声带更稳。

## 二、今天的三个发现

### 发现 ① 「粗尺子反而稳」（反直觉）

**#2 的答案在 5 轮里有 4 次不一样，但它的分数每一轮都恰好是 1.00。**

原因：`keyword_recall` 只看**关键词有没有出现**，不看措辞。

> **粗尺子滤掉了措辞噪声，所以在「答案换个说法」这件事上，它反而比人稳。**

**教训**：指标的「敏感度」和「稳定性」是一对矛盾。想要它抓住细微变化，就得接受它跟着噪声一起抖。

### 发现 ② 一个完全没预料到的失败模式：Unicode 下标

**`CO₂` vs `CO2`** —— 化学式里的下标 `₂`（U+2082）在文本里是**另一个字符**，不是「2」。

`keywords()` 里 `re.sub(r"[^a-z0-9\s]", " ", text)` 会把 `₂` 变成空格 → 标准答案里的 `co` 和生成答案里的 `co2` **对不上** → 漏判。

**这属于第 ④ 类缺陷（字符编码）的实例**，之前只在概念上知道，今天是**实测撞上的**。

### 发现 ③ `keyword_recall.py` 里有死代码（我写的疏漏）

`keyword_recall(gt, gen)` 这个**单题版函数，没有被任何地方调用**。

对比 `evaluator.py`：那里的 `hit()`（单题）**是**被 `compute_hit_rate()` 调用的。所以新文件破坏了对称——而且违反了我自己讲的「**算分规则只能有一份**」：`compute_keyword_recall` 里把公式又抄了一遍。

**已修**：让 `compute_keyword_recall` 调 `keyword_recall`，算分只此一处。代价是 `keywords()` 每题多算一遍（20 题的规模可以忽略），换来对称和单一来源。

## 三、踩的坑

### `⚠️` emoji 在 Windows GBK 控制台崩溃

```
UnicodeEncodeError: 'gbk' codec can't encode character '⚠'
```

**排查**：逐个字符试 → 只有 `⚠`(U+26A0) 和 `️`(U+FE0F) 过不了 GBK；**中文、`×`、`→`、`≥` 全都没问题**。

**对策**：脚本里别用 emoji，用 `[!]` 这类 ASCII 标记。

### VSCode 的 ▷ 按钮不传参数

▷ 只执行 `python 这个文件`。要 `--runs 5` 得**在终端手敲**。中文乱码就 `chcp 65001`。

## 四、概念收获

| 收获 | 内容 |
|---|---|
| **尺子 vs 铁** | `keyword_recall` 这个**函数本身 100% 确定性**。噪声不在尺子里，在**输入**（大模型生成的答案）里 |
| **噪声带不跨配置** | 改了 prompt / top_k / chunk_size → **必须重测**。旧带宽对新配置无效 |
| **n=2 会被运气骗** | 两个数字不是「带」。N ≥ 5 才算 |
| **函数收「数据」不收「文件名」** | 今天看到了它的**用处**：正因如此，`compute_noise_band` 才能把「第 r 轮拼出来的假 answers」喂进去复用 |
| **结论 + 明细一起返回** | `(avg, rows)` / `(scores, min, max)` —— 一个数字的诊断力是 0，必须留一条路让人看到「这分数怎么来的」 |
